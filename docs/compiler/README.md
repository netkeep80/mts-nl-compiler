# W21 — Веб-эксперимент Link Compiler

Открыть в GitHub Pages после принятия изменений: **https://netkeep80.github.io/mts-nl-compiler/compiler/**

Это статическая браузерная страница, изолированная от серверной базы данных. Фразы не отправляются в сеть. Вручную введённый Unicode-текст (до 2048 code points, включая emoji, управляющие символы, пробелы и переводы строк) разбивается и точно восстанавливается из созданной структуры.

## Режимы

1. **Balanced**: бинарное дерево, деление на половины (с интернированием повторных пар).
2. **Left**: последовательное левое дерево (также с интернированием).
3. **Re-Pair**: локальное самообучение на *том же самом тексте*. После подсчёта частот смежных текущих токенов алгоритм выбирает самую частую допустимую пару с детерминированным разрешением равенства. Проверяет количество фактических **неперекрывающихся** замен, а не подставляет перекрывающуюся частоту. Правило определяет новую целочисленную метку и исходные левую/правую части. Алгоритм ограничен 128 правилами, максимумом 256 скаляров в правиле, вводом 2048 скаляров.

Код Re-Pair адаптирован из **`src/universal-repair-numeric-v0.mjs`** (исследование W4), но браузерная версия **не является** production SQLite-компилятором. В W4 словарь учится на независимом train corpus и физические Link ID выделяются SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`. Здесь обучаемые метки правил и Link-номера являются локальными целыми индексами сеанса. Нет persistent базы, скрытого разделения train/heldout и обученного LM.

## Интерпретация метрик

- `uniqueAtoms`: число разных наблюдённых Unicode scalar atom Link, достижимых от корня.
- `uniquePairs`: число уникальных бинарных пар `(from,to)` в интернированном DAG.
- `expandedPairOccurrences`: число внутренних узлов в **полном развёрнутом бинарном дереве**; для непустого текста из N скаляров равно N−1, независимо от способа группировки.
- `reusedPairOccurrences=expandedPairOccurrences−uniquePairs`: сколько экземпляров внутренних пар заменено ссылками на уже имеющиеся уникальные пары. Это **структурная** экономия экземпляров, а не физическое сжатие SQLite/байтов/MDL.
- `topPairs[*].uses`: число использований Link в полном развёрнутом исходном дереве. Это **не** `from_uses/to_uses` физического хранилища и **не** частота исходного символьного ряда.
- `utf8Bytes`: длина исходного текста при кодировании UTF-8. Не является длиной сериализованного Link графа.
- `learnedRules`: количество Re-Pair правил, найденных на **этом же вводе**. Не semantic correctness или OOD generalization.

Все три режима проходят exact Unicode replay из корня. Пустая строка даёт `EMPTY_INPUT`. Одинокие суррогаты UTF-16 и ввод вне лимита отклоняются. Таблица Link показывает полюса, значение и числа использований; дерево отображается с ограничением по глубине для безопасности UI.

## Проверки

```bash
npm test
node --test tests/web-compiler.test.mjs
```

Тесты контролируют roundtrip (составные Unicode, emoji, NUL, CR/LF), структуру на «мама» (2 уникальные пары balanced против 3 left), фактическую неперекрывающуюся замену (`ааа` даёт 0 правил при пороге 2, `аааа` даёт 2 замены), детерминизм, ресурсные ограничения, а также реальные события UI в безопасном DOM-mock без сетевых зависимостей.

Коротко: **это демонстратор корректного Link DAG и частотной группировки, а не действующая модель понимания языка, исправления требований, Г и вероятностного обучения**. Научная разработка компилятора продолжается в [issue #97](https://github.com/netkeep80/mts-nl-compiler/issues/97).
