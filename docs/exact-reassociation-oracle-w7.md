# W7 — точный оракул стоимости перегруппировки Link (исследование)

## Научное различение
`from_uses` и `to_uses` в `db/schema.sql` — число **физических**
полюсных ссылок из всех строк `links` (даже недостижимых),
не число вхождений Link в раскрытие документа и не число ссылок
в корневом лесу. Частоты наблюдений отдельных подстрок, структурная
дедупликация и достижимость — разные величины.

Для заменяемого корня `A`, предлагаемого корня `B`, и неизменяемых
опубликованных корней `U` сравниваются замыкания `Reach` по полюсам:

```
Before = Reach(U ∪ {A})
After  = Reach(U ∪ {B})
Δreachable = |After \ Before| - |Before \ After|
```

Отрицательное значение означает уменьшение числа **уникальных достижимых**
Link. Оно **не** означает немедленное уменьшение физического числа строк
SQLite: без garbage collection старые Link сохраняются, а новые добавляются.
Отдельно оцениваются:

- `introducedLinkCount`: все ранее недостижимые Link, включая
  физически существовавшие, но вновь активированные;
- `retiredReachableLinks`: сколько Link исчезло из замыкания корней;
- `newPhysicalRows` и `physicalRowDeltaWithoutGc`:
  сколько новых строк реально потребуется выделить при выбранной
  стратегии интернирования.

## Контракт экспериментального оракула

1. Работает исключительно с физическими `Link ID`, созданными SQLite.
   Списки `frontier` состоят из 4, 5 или 6 **готовых Link-листьев**:
   каждый лист вправе раскрывать произвольную Unicode-последовательность.
   Все полюса должны существовать.
2. До оценки проверяется равенство точного раскрытия исходного
   `oldRoot` и конкатенации раскрытий `frontier`. Любая неэквивалентная
   замена блокируется.
3. На неизменяемом снимке SQLite перебираются все 5/14/42 полных
   бинарных группировки. В каждом виртуальном варианте повторно
   используется старейший допустимый физический Link с точно теми же
   числовыми полюсами. Условие `UNIQUE(from_id,to_id)` не вводится.
4. Реальная функция выбора — минимизация `Δreachable`, затем
   минимизация числа новых физических строк, затем стабильный
   порядок дерева. Без строго отрицательного `Δreachable` замена
   **не выполняется**.
5. Материализация производится после получения `BEGIN IMMEDIATE`
   и **повторного** построения плана под write-lock. Новые физические
   строки записываются топологически, счётчики восстанавливаются,
   целостность SQLite проверяется перед `COMMIT`. На ошибке — `ROLLBACK`.
6. **Ограничение:** в v0 нет атомарной долговечной публикации
   корней документов вместе с новой структурой, нет GC, нет алгоритма
   выбора перекрывающихся окон во всём документе. Возвращаемый
   `rootLinkId` должен быть отдельно сохранён вызывающей стороной.
   API явно маркирует `rootPublication=EXTERNAL_NOT_ATOMIC`.
   Следовательно W7 — исследовательский оракул, а не production rewrite.

## Проверки
Синтетический пример с закреплённым `cd` и исходным
`(((ab)c)d)` подтверждает измеримое уменьшение уникальной
достижимости на один Link при перегруппировке в `(ab)(cd)`.
Физически при этом **добавляется** одна строка SQLite, пока нет GC.
Проверка фиксирует оба числа независимо. Дополнительно тестируются:
удержание старого корня внешним пином, точная Unicode-последовательность,
побайтовый холодный replay, число деревьев 5/14/42,
допустимые дубликаты пар, отказ при несовпадении раскрытий и
транзакционный откат на ошибке SQL.

## Следующие фальсификаторы
- Допустить регистрацию корня и замену в одном принятом транзакционном
  authority-механизме; проверить crash/rollback и повторный replay.
- Ввести достижимый GC с проверкой физического числа Link (документировать
  исключения для неподконтрольных корней).
- Обеспечить согласованный batch неперекрывающихся окон и инкрементальную
  оценку `Reach`, иначе полный проход по миллионам физических строк
  для каждого нового символа будет слишком дорог.
- Выполнить контролируемое сравнение 4/5/6 на том же 60-книжном корпусе
  **после** реализации атомарной публикации корней, не смешивая
  эту стоимость с эвристическим W6.
