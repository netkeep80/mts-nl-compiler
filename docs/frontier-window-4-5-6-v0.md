# W6 — фальсификация ширины скользящего фронта 4/5/6

## Вопрос
Даёт ли просмотр последних 5 или 6 точных Unicode-символов выигрыш
по сравнению с 4 символами, если язык, пробелы, слова и словари неизвестны?

## Воспроизводимый протокол
- Корпус: ровно те же закреплённые 60 книг, 48 train / 12 heldout
  (индекс modulo 5 равен 4); из train берём первые 16 384 скаляра
  каждой книги, heldout при обучении не читаем.
- Три **отдельные** независимые SQLite-базы: окна 4, 5, 6. Равные
  `maxSelectedPhrases=384`, `minOccurrences=3`, одни и те же Unicode
  символы, лимиты, train/heldout и базовое бинарное хранилище.
- Первый проход формирует неизменяемый снимок частот **всех** подстрок
  длин 2..w, отдельно `observed` (перекрывающиеся наблюдения) и
  `disjoint` (максимально раннее детерминированное неперекрывающееся
  множество на каждом документе). Оба счётчика — наблюдения,
  НЕ физические ссылки на Link.
- Второй проход: с приходом очередного скаляра берём последние `w`
  символов. Перебираем **все** полные бинарные структуры на них
  (числа Каталана 5/14/42). Для каждого внутреннего поддерева
  добавляем `log2(1 + disjoint[subphrase])`. При равенстве
  применяется стабильный порядок перебора разбиений.
  Одинаковые текстовые окна кэшируются; число действительно
  рассчитанных бинарных деревьев отдельно фиксируется.
- Победившие поддеревья голосуют за кандидатов, затем по
  `(disjoint - 1) * (length - 1)` отбираются до 384 фраз.
  Вновь оптимизируем их формы тем же исчерпывающим перебором.
  Физические Link создаются только штатным числовым хранилищем
  SQLite с рекурсивными левым и правым полюсами.
- Все 60 книг компилируются из исходных байтов; все корни
  читаются независимо с холодным побайтовым восстановлением.
  В каждой базе сохраняются только реально достижимые структуры.
- Артефакт: `reports/large-corpus-performance.json.frontierWindows`.
  Сопоставлять физические Link, размер VACUUM SQLite, train/heldout
  покрытие, время построения словаря и число фактически
  оценённых деревьев. Не выдавать долю покрытых символов
  за коэффициент сжатия.

## Ограничения интерпретации
Это **скользящее окно поиска кандидатов**, а не постоянно изменяемый
онлайн-граф: частоты заморожены на момент перебора, а 60 исходных
документов кодируются через greedy longest exact match по обученной
грамматике. Поэтому измеряем изменение результата *при выборе ширины
окна*, а не выигрыш полного динамического перепарсинга ранее
созданных Link. Для следующего шага нужно отдельное сравнение с
онлайн-перегруппировкой и атомарным обновлением рефкаунтов.

Алгоритм специально не реализует распознавание слов, нормализацию
Unicode, поиск грамматического минимума или параллельные мутации.
Снимок частот и изоляция словаря позволяют безопасно
распараллеливать отдельные окна позднее; текущий прогон —
однопоточная проверка качества, без заявления об ускорении.
