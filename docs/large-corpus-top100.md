# Корпус 60 крупных русскоязычных произведений и обязательный TOP 1000

[Авторское решение #65](https://github.com/netkeep80/mts-nl-compiler/issues/65). В отдельный **добавочный** набор включены ровно 60 реально существующих произведений десяти классических русскоязычных авторов из единого неизменяемого Git-источника d0rj/RusLit. Полная совокупность — 19 701 816 байт исходного UTF-8; каждый объект проверяется по известной длине и выбранному пути на точном git commit. Права на оригиналы могут зависеть от страны, перевода и редакции. Исходные тексты **не коммитятся** в этот репозиторий и не попадают в отчёты.

Этот новый тракт не использует хеш для построения Link вообще: каждый Link получает 64-битное SQLite AUTOINCREMENT; идентичность не вычисляется из текста или пары полюсов. Совпадения атомов и дуплетов выявляются **явным точным сравнением** в памяти: разные связи с одинаковыми полюсами разрешены схемой и могут не склеиваться. SHA идентификаторы старых E1–E7 не должны становиться идентификаторами в новой БД. Внешний Git commit нужен для воспроизводимости источников, а не для Link identity.

## Полная сборка

Запуск из checkout проекта при наличии корпуса в .sources/ruslit:

node --expose-gc --max-old-space-size=5500 scripts/build-large-corpus.mjs

Перед сборкой необходимо получить указанный исходный репозиторий на конкретном commit, не на плавающем main. Специальный CI workflow должен публиковать результаты одной сборки и **падать, если какого-либо документа нет** или не создан полный TOP1000.

Каждая успешная сборка выдаёт:
- reports/knowledge-large.sqlite — БД с 64-битными идентификаторами.
- reports/top-1000-links.json — строго 100 самых частых наблюдаемых *структурных* Link, считая каждое их раскрытое вхождение в исходный текст, с числовым Link ID, полюсами, количеством исходных вхождений, количеством документов, длиной раскрытия и коротким превью.
- reports/top-1000-links.md — читаемая таблица TOP1000 связей и дополнительные таблицы TOP1000 слов, биграмм и триграмм.
- reports/large-corpus-performance.json — время/скорость загрузки **каждой книги** и полного корпуса, реальное число созданных и переиспользованных Link, rebuild/integrity/VACUUM/cold-replay, bytes/RSS, версии Node и SQLite.

Все частоты являются **наблюдательными** и строятся только по исходным книгам. Ни счётчики from_uses/to_uses (уникальные структурные дуги), ни выводимые правила, ни реконструированные доказательства не должны увеличивать частоты наблюдений.

TOP1000 Link: счётчик увеличивается при каждом построении парного узла исходного сбалансированного дерева, в том числе при повторном использовании ранее существующего числового Link; знаменатель — общее количество таких событий, равное сумме (длина документа в кодовых точках – 1). Это **не** вероятностная модель слов. Одновременно из исходных буквенных последовательностей с приведением к нижнему регистру строятся точные частоты слов и последовательностей двух/трёх слов; знаки конца предложения .!?… разрывают фразы. Для каждой категории указан собственный знаменатель числа позиций. Процент/отношение частоты не означает, что в MTS принят probabilistic Link weight.

## Согласованность и пределы

Транзакция — одна книга. Система отклоняет невалидный UTF-8, неподтверждённые размеры источников и неполный набор. Публикация TOP1000 возможна только после successful COMMIT всех документов, пересчёта счётчиков и полного побайтового cold read-only восстановления исходников. Отчёт старого 6-документного E0 сохраняется **отдельно**, не сравнивать скорости разных алгоритмов без matched-run benchmarking.

Особенность версии 1: структурный компилятор пока использует сбалансированное построение DAG, а не научно принятую сегментацию слов/предложений и не production Γ. Частотные n-граммы дают первую наблюдаемую картину, но ещё не являются обученной семантической вероятностной моделью. Расширение E1–E7 и исправление качественной сегментации остаётся отдельной работой, без возвращения хешей в Link identity.

TOP-1000 is a strict build gate for each of four observed rankings. Every full database build must generate all 1000 entries per category, with source counts, numerical Link identities, and the complete performance report. An incomplete ranking fails the build.
