# N3 — переход канонической SQLite на 64-битные ID Link

Основание: прямое решение автора [#51](https://github.com/netkeep80/mts-nl-compiler/issues/51). Эта стадия содержит **защищённый** `db/schema.sql` и не должна объединяться без проверки полной регрессии и независимого авторского разрешения для точного пути.

Физическая модель:
- `link_id INTEGER PRIMARY KEY AUTOINCREMENT` с положительным signed 64-bit ID; не `TEXT` и не хеш полюсов;
- `from_id INTEGER`, `to_id INTEGER` с отдельными обычными индексами `idx_links_from`, `idx_links_to` и отложенными ссылками на ту же `links`, допускающими циклы в атомарном batch;
- `string`, `weight`, `from_uses`, `to_uses` сохраняют прежние ограничения/смысл. Не введено `UNIQUE(from_id,to_id)`. `sqlite_sequence` — системная метаинформация SQLite AUTOINCREMENT, а не предметная таблица Links.

Единственным источником физического DDL является `db/schema.sql`: модуль `src/numeric-link-store-v1.mjs` читает этот файл. Текстовые ID старых E0–E7 и исследовательских JSON используются **только как внешние временные ключи импорта** через N2; в предметную SQL-таблицу всегда записываются BigInt numeric IDs. Миграция сохраняет старую Link-графовую структуру, параллельные экземпляры, подписи, веса и циклы. Для научных legacy-oracles сохранены исходные внешние метки, чтобы можно было сравнить результаты до и после миграции; они не являются физическими Link ID.

`sqliteReplay` выполняет реальное восстановление содержимого через **numeric** Link root, а не просто равенство старого текстового графа. Физическая база знаний `knowledge.sqlite` строится детерминированно из упорядоченного внешнего источника, проверяется независимым холодным read-only consumer и явно маркирует тип ID `sqlite-signed-int64-autoincrement`. Логический SHA документа остаётся контрольной суммой источника, а не идентификатором Link.

Точки отказа: неверные исходные связи, отсутствие полюса, переполнение signed-64, конкурирующие явные ID, недопустимые веса, нарушение foreign key, частичная транзакция. Нельзя молчаливо сопоставлять один и тот же numeric ID из **разных** SQLite файлов: он локален для конкретного хранилища.

**Проверяемые ограничения:** N3 не делает E0–E7 промышленным семантическим компилятором; не добавляет production Γ; не определяет семантику весов; не выпускает версионированный архив и не переносит автоматически сторонние существующие SQLite файлы. После выполнения полной регрессии требуются отдельные метрики физического количества Link/bytes и cold replay по всем закреплённым исходным корпусам. Результаты исторических исследований на хеш-адресованных *временных метках* и новые физические измерения нельзя сравнивать без указания представления.
