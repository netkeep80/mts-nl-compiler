# N2 — миграция старых пятиколоночных Link на SQLite 64-bit ID

Этап N2 расширяет экспериментальный N1 (#60), не меняя принятые контракты \`db/schema.sql\` или МТС v0.15.

В прежних экспериментах каждый Link имел текстовый \`link_id\`, в том числе генерируемый из хеша структуры. При импорте **текстовый ID сохраняется только во входной временной таблице соответствия**, используется для разрешения полюсов и затем заменяется **числовым идентификатором SQLite**, созданным через \`INTEGER PRIMARY KEY AUTOINCREMENT\`. Обратная реконструкция старого экспорта возможна лишь пока потребитель отдельно хранит именно эту карту соответствия: физическая база не содержит старых текстовых ID и не обязана их восстанавливать.

\`migrateLegacyLinks(db, rows)\` проверяет полный набор ровно пяти полей и ссылки между строками. Атомы, подписанные пары \`string\` и пары без подписи, \`null\`/0 вес, дублированные полюса с разными ID, циклы, самоссылки и Unicode сохраняются один-к-одному. Импорт выделяет ID в сортированном порядке **старых временных ключей**, что обеспечивает детерминизм в одной версии источника; это не смысловая канонизация пары. Отклонённый документ не публикуется, а поздние SQL-ошибки откатываются транзакцией N1.

\`decodeNumericSource(db, bigintRoot)\` восстанавливает ациклический исходный текст по полюсам **новой физической асети**, независимо от сохранения текстовых старых ID. Циклический source-root получает явную ошибку; для обычного графа из E0 structural DAG возможна проверка байтового Unicode-совпадения.

**Оставшиеся архитектурные границы.** Пока нельзя менять \`db/schema.sql\` без полного переноса \`src/store.mjs\`, \`src/real-corpus-e0.mjs\`, \`src/knowledge-snapshot-v0.mjs\`, всего тестового и CI-корпуса и отдельного подтверждения изменения protected path. Сравнение физических Link count/байт требует полного корпуса E0–E7 на новой схеме; прежние content-addressed строки считать только Legacy source labels. Между независимыми SQLite базами одинаковый числовой ID не означает одинаковую Link-identity; объединение требует проверяемого явного id-map и версии authority.

Никаких физических хешированных идентификаторов новым кодом не создаётся, никаких решений по семантике веса или АГИ не предполагается.
