# E5 — событийный индекс наблюдённых пар и адресный пересмотр старой view

Исследовательский контракт #40; **не исполнение native Γ/MP**, не изменения accepted МТС v0.15 и не утверждение инкрементальной перестройки **всего** физического графа.

## Область подтверждения

- Исходный поток — Unicode scalar последовательность. Первичное построение частотного индекса требует один полный проход по исходному источнику. После одного внешнего наблюдения в конце индекс проверяет **один** новый соседний контакт, обновляет числовую частоту (не probability/weight) и позицию изменённой пары в индексированной max-heap. Heap содержит один объект на различимый смежный pair, не тысячи stale-version записей.
- Детерминированный лидер \`count descending; pair(a,b) lex ascending\` совпадает с полным сканированием для top-1; пары могут перекрываться. Обновление source и внешнего event-id ledger идемпотентно; несовпадающий повтор того же ID отклоняется.
- Старые watch spans подписываются на те пары, которые содержат. Если выбранное правило \`ab\` сменилось на \`cd\`, очередь получает только views, где наблюдалась хотя бы одна из этих пар. Остальные пробные views не пересобираются. Лимит \`maxWatchers=0\` даёт честный RESOURCE_LIMIT, а не ложный QUIESCENT. После адресного replay сохраняются старый и новый roots. Новые proof-Links **не считаются новым внешним наблюдением**.
- Каждая watch view строится из обычных content-addressed atom/pair Links, по тому же content-anchored grouping E3; в приложении доказаны exact Unicode source и byte equality, idempotent replay, контроль пустого и неправильного ввода, сопоставимость идентификаторов root с независимым полным E4 batch oracle.
- Подсчёт \`selectedProbeAndRule\` и \`retainedProbeAndRule\` охватывает только зарегистрированные watched views и выбранный structural rule: **не** всю исходную сеть, контексты, доказательства или все Link-кандидаты. Поэтому нельзя сравнивать абсолютные расходы E5 с полным E4 как равнозначные показатели global MDL.

## Фальсификатор

Исходник \`ab×6000+cd×6000+c\` = 24 001 кодовая позиция. Одно поступившее \`d\` должно изменить лидера \`ab(6000)\` → \`cd(6001)\`, вызвать пересмотр старого фрагмента \`ab×128\`, находящегося за 23 745 позиций от конца, и **не** потревожить подписчика на единственную пару \`bc\`. Проверка каждых последовательных Unicode scalar входных символов с независимым oracle полного повторного сканирования обязана находить ровно тот же лидер.

## Следующее научное требование

Интегрировать agenda в авторитетные selected Link-context/Γ M-state generations, добавить durable provenance, динамику по 0/1/N правилам, индекс зависимостей Link→rules→spans, независимый full-graph reference для cost/retention; тогда будет предмет для заявления об инкрементальной Γ. Текущий E5 — только наблюдательный front/scheduler.
