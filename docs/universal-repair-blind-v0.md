# W4 — универсальное рекурсивное выделение повторов в числовые Link

Авторская гипотеза: знание пробелов/слов не должно быть необходимым для обнаружения частых последовательностей. Отличие от старого balanced-character — **структуру строим из обнаруженных повторений**, а не ищем совпадения только в готовых сбалансированных поддеревьях.

Алгоритм `trainUniversalRepair` — ограниченный по ресурсам, Re-Pair-подобный эксперимент, **не** алгоритм гарантированного поиска минимальной грамматики. Вход — только точные Unicode scalar values; без токенизации слов, распознавания пробелов, грамматических правил, регистронезависимого сравнения и статистических предубеждений о языке. Для каждой обучающей книги берётся начальный точный фрагмент (не более 16 384 символов); никакой текст из held-out не анализируется при построении словаря. Выбор 48 train и 12 held-out детерминирован: нулевой индекс книги modulo 5 равен 4 → held-out.

На каждой итерации подсчитываются все смежные пары **текущих** токенов грамматики, выбирается наиболее повторяемая (частота + детерминированное разрешение равенства), выполняется замена без перекрытия. Формируются новые *локальные* метки токенов и очередные уровни структуры. Максимум 96 правил, длина развёрнутого правила не более 64 символов и минимум 3 реальные неперекрывающиеся замены. Внутренние целые метки грамматики НЕ являются persistent Link identities.

Для компиляции всех 60 книг строится точный префиксный автомат из изученных развёрнутых правил. При загрузке применяется максимально длинное совпадение **без семантических границ**. Каждый найденный токен разворачивается в физический бинарный Link через SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` и явное переиспользование по фактическим числовым полюсам. Оставшиеся одиночные символы и связи верхнего уровня строятся той же бинарной моделью. На выходе один корневой Link на каждый полный исходный документ; 60/60 документов обязаны восстановиться побайтово через холодную read-only SQLite.

Контрольные метрики W4 в `reports/large-corpus-performance.json.universalRepairAB`: число обучающих правил; сколько позиций исходных Unicode-символов покрыто выбранными структурами в train и в held-out; реальные частоты выбранных Link и длины развёртываний; физические Link, размер VACUUM SQLite, вставки/с, тайминги и холодный replay; отношения к balanced-character и word-aligned на точно тех же 60 исходниках. Исходные книги и саму структуру не публикуем целиком.

**Ограничения:** 16k начальных символов каждой из 48 книг могут не отражать весь корпус; обучение не глобальное по всем текстам. Простое жадное longest-match может быть хуже оптимальной сегментации. Train/held-out покрытие измеряет частоту буквальных повторений изученных фрагментов, а не предсказательную вероятность или семантическое обобщение. Скорость сравнивается в фиксированном порядке на CI и не доказывает причинного ускорения. Успех — только наблюдаемые числа после полной сборки.

Тесты подтверждают рекурсивные правила длинее двусимвольных пар, сохранение управляющих символов и Unicode, физическую достижимость изученных узлов, rollback на SQL исключении, отсутствие утечки held-out в train, 48/12 split и полный холодный replay. Старые E1–E7 исследовательские SHA-ключи остаются отдельным нерешённым вопросом #63, но этот алгоритм SHA-ID Link не создаёт.

Следующая фальсификация: качественное сравнение числа Link/байт/скорости/длины и значения покрытий с word-aligned. Только после этого — изменение эвристик частоты, окна и выбора кандидатов, с постоянным exact-source регрессионным контролем.
