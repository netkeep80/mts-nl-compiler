# W10 — различимые атомы, пробелы и настоящие деревья Link

Этот PR относится **только к диагностике**. Он не меняет компилятор, нормализацию, атомизацию, принятые требования МТС v0.15 или SQLite-схему.

## Как читать обновлённый `reports/top-1000-links.md`

- **Атомы:** отдельный раздел `Source atomic Link frequency`, включающий числовой физический `Link ID`, точный JSON символа, видимый знак, частоту раскрытых *листьев* (полный источник) и число книг. Счётчик суммируется по реальным вызовам создания/повторного использования атомов при каждой компиляции документа, а не по `from_uses/to_uses`.
- **Дуплеты:** таблица показывает `Link ID`, `From/To`, число событий построения соответствующего узла сбалансированного дерева, длину, точный `JSON` и ограниченный фрагмент в `⟦...⟧`. `⟦` и `⟧` отмечают **начало/конец отображаемой строки**, НЕ факт границы строки в источнике. Пробел `␠`, LF `␊`, CR `␍`, tab `␉`, NBSP `⍽`, BOM `⟨BOM⟩`; отражение не меняет байты данных.
- **Дерево:** компактная скобочная запись реальной физической группировки, **без ID внутри выражения** и без одной наружной пары корня: `мама → (ма)(ма)`. Скобки охватывают внутреннюю Link-пару, атомы выводятся непосредственно: `((мо)(пед))` только если именно так построено физическое дерево. Пробел в выражении пишется `␠`, а оригинальные круглые скобки и символы `␠` при буквальном присутствии в источнике экранируются обратной косой чертой; структура не получает лингвистических подсказок. Поля `Link ID` и `From/To` по-прежнему сохраняют физические числовые идентификаторы корня и непосредственных полюсов. При превышении лимита 2048 раскрываемых составных узлов возвращается явная метка `⟨TREE_LIMIT_EXCEEDED⟩`, `treeTruncated=true`, а не ложная полная структура.
- **Проверяемые примеры**: `мама → (ма)(ма)`; физическая сбалансированная группировка строки `мопед не мой` в текущей реализации равна `((м(оп))(е(д␠)))((н(е␠))(м(ой)))`. Она не похожа на «оптимальную морфологию», и именно это мы хотим видеть: не выдумывать красивые границы, а диагностировать фактические.

- Строка `", "` и строка `" ,"` **наглядно различаются** как `⟦,␠⟧` и `⟦␠,⟧`; JSON подтверждает различие.
- **Самополярность** `from_id=to_id` — это допустимая составная Link, например два пробела. Это **не** атом. Атом текущей схемы — `from_id=to_id=NULL` с заполненным `string`. Самозамыкание как альтернативное определение атома потребует отдельного решения Автора.

## Независимый аудит частот

Дополнительно полная сборка выдаёт `reports/frequency-audit.{json,md}`:
1. Чистые (без нормализации) Unicode scalar counts по исходным документам.
2. Перекрывающиеся позиционные биграммы/триграммы независимо от разбиения.
3. Число соответствующих узлов физического сбалансированного дерева для тех же текстов.
4. Проверка точного равенства **суммы** атомарных событий и независимого source histogram.
5. Проверка сохранения числа структурных событий = sum(max(0, codepoints-1)).
6. Дубликаты физических Link по одной и той же строке агрегируются только при аудите текста; разные ID остаются различными объектами.

Слогоподобные 2–3 кириллических последовательности с одной написанной гласной представлены **только как постфактум диагностический фильтр**, не лингвистическая истина и не подсказка алгоритму.

Принципиальное различие: позиционное число `оо` в `ооо` равно 2, а число сбалансированных Link-узлов `оо` может быть 1. Поэтому показываем **обе** объективные метрики, не называя события сбалансированной бинаризации «всеми вхождениями подстроки».

## Авторитетность результатов

Честный статус на момент подготовки: тесты могут подтвердить алгоритм, но для **количественной таблицы именно 60 книг** нужен новый полный прогон pinned-корпуса с созданием новых артефактов. Старый `top-1000-links.md` не станет автоматически новым отчётом. Нет изменений `db/**`, `requirements/**`, `.github/**` и политики.
