# W13 — полный корпус: объективная частота исходника перед Link, физическая SQLite

Статус: **исследовательский эксперимент, не изменение принятых MTS v0.15 и SQLite-схемы**. Исходные книги не публикуются.

## Данные и протокол

- Исходник: [точно закреплённый корпус 60 книг, workflow W10 #38253156259](https://github.com/netkeep80/mts-nl-compiler/actions/runs/38253156259), артефакт numeric-60-books-sqlite-top1000, с физическими исходными корнями и отчётом large-corpus-performance.json.
- Объём: **11 017 443 Unicode scalars / 19 701 816 UTF-8 bytes**, 60 книг.
- Обучение: ровно 48 книг, индексы с index modulo 5 != 4. **12 отложенных книг** не участвуют ни в каких частотах, выборе границ или коэффициентов при проверке.
- Граница после U+0020 — **замороженный параметр**, выученный W11 на префиксах *только train*, а не встроенная логика пробела. Код W13 читает любой скаляр из флага boundary-hex; не содержит лингвистических словарей, классов символов и подсказок на начале слова.
- Объективная статистика: все перекрывающиеся сырьевые последовательности длины 2–8, независимо от первоначальных деревьев. Рекурсивные разрезы не используют наблюдённые частоты уже сформированных Link.
- Фактор minObservedOccurrences = 2: исходные n-граммы с единичным наблюдением **не получают бонуса за переиспользование**, но их байты не исчезают.
- Выбор бинарного разреза внутри ранее найденных частей — жадный максимум:

  **S(L,R) = log₂(1+f_train(L)) · |L|² + log₂(1+f_train(R)) · |R|² − 0,1 · ||L|−|R||.**

  Для длины больше восьми f_train=0; для длинных отрезков проверка разрезов у двух краёв (до восьми символов) и в центре эквивалентна проверке всех разрезов для этого *локального* S. Это **не** глобальный минимум грамматики и **не** полный MDL в битах.
- Обычные числовые физические Link с парой из полюсов в точной однотабличной W10-DDL. Создаются структурные from_uses/to_uses, выполняются PRAGMA integrity_check, foreign_key_check, VACUUM и независимый read-only replay всех 60 корней.

| Модель | Физических Link | SQLite после VACUUM, байт | Точность |
|---|---:|---:|---|
| Исходная сбалансированная W10 | 2 747 870 | 120 221 696 | 60/60 |
| Word-aligned с внешними границами слов | 2 031 925 | 87 232 512 | 60/60 |
| **W13, source-first, min=2** | **1 951 822** | **83 890 176** | **60/60** |

- Против исходного balanced: **−796 048 Link (−28,97%)**, **−36 331 520 байт SQLite (−30,22%)**.
- Против word-aligned: **−80 103 Link (−3,94%)**, **−3 342 336 байт SQLite (−3,83%)**.

- SQLite integrity_check: **ok**; foreign_key_check: **0 ошибок**; counters восстановлены как структурная степень, не source-frequency.
- Независимый холодный побайтовый replay: **60/60 книг PASS**. Два полных запуска с идентичным алгоритмом дали **побайтово идентичную SQLite (SHA-256 58962eb54496b7f695c61f4d4597f258acdae69ca18349cff4065e030cfb1f35)**.

## Проверка на 12 отложенных книгах

Частоты выучены **только на 48 train**, затем сравнили W13 с обычным balanced **внутри тех же самых замороженных фрагментов**.

- Раздельное кодирование каждой отложенной книги: **12/12 улучшений**; средняя экономия **2 619,92 Link/книгу (5,14%)**, медиана 2 518.
- Описательный paired-bootstrap среднего (10 000 повторений документов с возвращением, seed 20261012): **95% percentile-интервал 2 054,75–3 212,17 Link/книгу**.
- Общее число Link для 48 обучающих книг: **1 647 573 → 1 602 726**, сокращение на 44 847.
- Новых физических типов Link при добавлении 12 отложенных к общему графу: **355 170 → 349 096**, экономия 6 074.
- Это **статистика 12 фиксированных русских книг**, не обобщаемая автоматически на другие языки или семантические задачи.

## Воспроизведение

Нужны Python 3.10+ (только stdlib) и два файла из W10-артефакта. Оба извлекаются из уже проверенной GitHub Actions SQLite-базы, новые исходные книги и секреты не требуются.

Исследовательский скрипт: **scripts/w13_full_source_frequency.py**; быстрое тестирование: **python3 scripts/w13_full_source_frequency.py --self-test**.

Полная команда:

    python3 scripts/w13_full_source_frequency.py \
      --source-sqlite knowledge-large.sqlite \
      --source-performance large-corpus-performance.json \
      --boundary-hex U+0020 --minimum 2 --max-scalars 1000000 \
      --output-sqlite w13-full.sqlite \
      --report-json w13-full-result.json

Дополнительные контрольные запуски: менять только --minimum на 1 или 3; сравнивать полный graph count, сохраняя один и тот же порядок train/heldout.

## Чего результат пока не доказывает

1. Сжатие **в битах с учётом передаваемого словаря, корней и правил** пока не измерено. Размер SQLite и число Link — реальные физические метрики, но не полный MDL.
2. На русском корпусе явно часто встречается U+0020. Обнаруженная граница не доказывает выделения морфем и универсальности на языках без пробелов.
3. Результат получен жадным локальным алгоритмом, не строгой глобальной оптимизацией Link DAG.
4. Честный следующий этап: контрольная полная битовая кодировка M1, тесты на языках без разделителей, контекстно-продуктивные классы, затем публикация корней и безопасный GC (#78).
5. Измерение здесь **не** доказывает понимание смысла или получение AGI.
