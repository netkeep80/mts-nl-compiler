# W16 — архив инсталляционной Link-асети ≤100 МБ и расширение научного корпуса

Статус: **исследовательский пакет данных, не Windows `.exe`/`.msi`; никакого изменения принятых MTS v0.15, SQLite DDL, repo-policy или Author requirements**.

## Почему отделены три понятия

1. **Данные в архиве**: корневая Link-асеть и достаточные сведения для восстановления источников; это то, что ограничивает 100 000 000 байт.
2. **База после установки**: SQLite с индексами/счётчиками, больше архива; нужно учитывать место на диске и контроль целостности.
3. **Сам исполняемый компилятор/инсталлятор**: размер настоящего runtime пока не измерен. Для бюджета временно резервируем **10 000 000 байт**; выход за остаток блокируется. До сборки Windows-установщика нельзя утверждать, что его фактический размер подтверждён.

**Источник неизменных данных**: W13 exact-cold-verified полная база 60 произведений, [Draft W13 #83](https://github.com/netkeep80/mts-nl-compiler/pull/83), 
11 017 443 скаляра, 19 701 816 UTF-8 байт, 1 951 822 физические Link; 60 source SHA-256 и root Link-ID из точного W13 report.

|---|---:|---:|---|---|
| SQLite без сжатия | 83 890 176 | 83.89 | исходник | уже ниже лимита данных, но без запаса на растущий корпус |
| zstd -3 | 38 902 278 | 38.90 | совпадает | быстрый установочный вариант |
| zstd -9 | 31 901 745 | 31.90 | совпадает | хороший баланс |

| bzip2 -9 | 35 401 853 | 35.40 | совпадает | контроль |

Каждый архив декомпрессирован полностью и проверен побайтовым SHA-256 исходного SQLite. Измеренный 
`w16_corpus_bundle.py` упаковывает SQLite в XZ-6 внутри структурного ZIP без второго сжатия:

| Поле | Значение |
|---|---:|
| Реальный research-only `.zip` с manifest/root SHA | **20 704 765 байт** |
| Граница пакета + резерв установщика | **30 704 765 байт** |
| Бюджет (десятичные МБ) | **100 000 000 байт** |
| Оставшийся предварительный бюджет для научного корпуса | **69 295 235 байт** |
| Пустой резерв runtime | 10 000 000 байт |
| Восстановленная Link SQLite | 83 890 176 байт |
| Восстановление 60/60 исходных текстов по записанным корням/SHA | **PASS** |

Примечание: сам XZ-поток, полученный через внешнюю утилиту `xz -6 -T2`, **не битово равен** XZ-потоку Python `lzma` с профилем 6, поэтому 20 721 708 и 20 704 765 различаются. Оба независимо восстановлены и имеют одинаковый исходный SQLite SHA. Бюджет относится ко **всему** ZIP, а не только payload.

## Альтернативное представление: асеть дуплетов вместо SQLite

[W15 Draft #86](https://github.com/netkeep80/mts-nl-compiler/pull/86): самостоятельная Link-асеть с прогрессивными индексами занимает **9 723 277 байт**, её XZ-6 — **8 104 260 байт**. Этот путь существенно компактнее, но до использования SQLite потребуется **восстановить граф, построить индексы и провести root-replay**, то есть цена переносится с установки/диска на CPU и время. Это **не** готовая альтернатива рабочей SQLite без bootstrap-импортера. Не нужно одновременно вкладывать оба формата в дистрибутив без необходимости.

## Протокол научных книг и репродуцируемость

Исходные 60 русских классических книг взяты из `d0rj/RusLit` на commit `4509680428729da225a73a22008133660f92bb7e`. Его README утверждает общественное достояние, но требуется проверка конкретных произведений для территории распространения и условий использования. Не публиковать автоматически пакет с полными книгами как общедоступный дистрибутив по одному лишь claim репозитория.

В `docs/w16_science_corpus_candidates.json` указаны 11 источников литературы по логике, теории множеств, вычислимости, типам, категориям, дискретной математике, семантике, прагматике и основаниям МТС; **ни один ещё не загружен и не добавлен в W13-модель**. Предпочтительны исходные UTF-8 LaTeX/Markdown с юридически понятными условиями распространения; если из PDF выделяют текст, исходный PDF и извлечённые UTF-8 данные считаются **разными артефактами** со своими SHA/правилами извлечения. Никакой неявной нормализации.

В новом corpus-v2 сохранить неизменный набор 60 книг и его контрольные суммы; научные произведения составляют отдельный домен, без подмешивания в старые 12 heldout. Проверять *дедупликацию* общего материала Open Logic Project и его производных курсов, иначе возможна утечка между train и heldout. Один произведённый документ — единица split, а не произвольный абзац.

**Лицензирование**: Open Logic Project и PLFA указывают CC BY 4.0 (атрибуция), HoTT — CC BY-SA 3.0, PDF Category Theory for Programmers — CC BY-SA 4.0; Discrete Mathematics 3rd — CC BY-SA 4.0, тогда как 4th — CC BY-NC-SA 4.0, эти редакции нельзя смешивать. OpenStax требует отдельных разрешений для внедрения в generative-AI offerings и применяет NC-условия; в текущий план автоматического импорта не входит. Нельзя считать «доступно онлайн» разрешением на перепаковку.

## Инструмент

Скрипт `scripts/w16_corpus_bundle.py` работает на Python stdlib. Он создаёт детерминированный research-only ZIP с `manifest.json` и `links.sqlite.xz`; при установке проверяет SHA исходной SQLite, SQLite integrity, целостность количества физических Link и побайтовые SHA **всех** исходных документов, раскрывая Link-корни из SQLite. Существующий выходной файл никогда не перезаписывается; превышение 
`archiveSize + reservedInstallerBytes > 100 000 000` блокирует архив. Для Release нужно отдельно подготовить **полный per-work rights manifest**; простая публикация чужой книги на Github не равнозначна лицензии на репакетирование.

Исследовательская команда:

```bash
python3 scripts/w16_corpus_bundle.py \
  --sqlite w13-portable-full.sqlite \
  --report w13-portable-full.json \
  --out w16-research-60.zip --budget 100000000 --reserve 10000000

python3 scripts/w16_corpus_bundle.py \
  --verify w16-research-60.zip --restore w16-restored.sqlite

python3 scripts/w16_corpus_bundle.py --self-test
```

Для ввода научных произведений потребуются: лицензия, точный источник + commit/edition, доказательство права на включение, исходный SHA-256, extraction recipe, корневой Link-ID, source SHA и сравнение compressed bytes / SQLite bytes / train vs heldout metrics. **Никакого автоматического слияния с существующей research-грамматикой до отдельного A/B.**

## Следующие фальсифицируемые эксперименты

1. Сравнить реальные извлечения и время cold-install `W16 SQLite+XZ` против `W15 progressive+XZ → reconstructed SQLite`, с одинаковыми 60 документными SHA и одинаковым SQL schema. Измерять CPU RSS и p95.
2. Подготовить `science-v1` с двумя лицензированными книгами (OLP original sections + PLFA), отдельно поставить science-only heldout, исключить повторяющиеся тексты и объяснить эффект на MDL/Link count.
3. Повторить подбор `zstd-3/9/19`, `xz-6`, `zlib`, `bzip2` на corpus v2 и не обещать линейную компрессионную плотность.
4. Автоматический контролёр пакета: **100 MB включая installer** (полностью замеренный исполняемый размер), не более выделенного RAM и disk после установки; проверка холодного decode всего корпуса на Windows 10/11.

Два из новых лингвистических изданий имеют важную редакционную развилку: Analyzing Meaning издания 2018 — CC BY 4.0, а новая третья редакция 2022 — CC BY-SA 4.0; включать только явно указанную редакцию с точным SHA.
