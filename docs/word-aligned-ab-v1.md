# #68 W2 — одинаковые книги, два способа построения числовых Link

Accepted E0 остаётся посимвольной balanced-структурой. Это **исполняемый** независимый эксперимент A/B поверх тех же 60 закреплённых русских произведений; ни один Link не получает SHA-идентификатор.

Программа полной сборки E0 обязана сначала завершить подтверждённый hashless baseline с 1000 наиболее частых Link, слов, биграмм и триграмм; затем во второй SQLite в той же сессии с той же физической схемой загружает **все** исходные байты с word-aligned сегментацией и обязательным полным cold exact replay.

Сравниваются: число физических уникальных Link; время вставки новых Link и Link/с; размер VACUUM SQLite; число реально построенных достижимых целых слов и двух-/многословных узлов, число уникальных идентификаторов для них; этапы счётчиков, целостности, холодного восстановления. Все 60 книг должны восстановиться побайтово. JSON \`reports/large-corpus-performance.json.wordAlignedAB\` содержит измеренные A/B показатели, версии/основание внутри родительского отчёта. Счётчики наблюдений слов и phrases берутся от исходных Unicode строк; любой вновь переиспользованный Link НЕ порождает новых независимых наблюдений.

Точность интерпретации: balanced запуск происходит первым, word-aligned вторым. Возможны прогрев JIT, SQLite page cache, GC; коэффициенты времени — только описательные, **не доказательство ускорения**. Word-aligned строит физически достижимые словоформы и некоторые многословные узлы, но не гарантирует оптимальное покрытие всех повторяющихся фраз и не обучает семантические веса. Для строгой статистической оценки скорости понадобится порядок AB/BA, несколько прогонов, доверительные интервалы.

Запуск всей работы следует проверять на [полном CI workflow](https://github.com/netkeep80/mts-nl-compiler/actions/workflows/large-corpus.yml); в отдельных unit-тестах проверяется на маленьком fixture с Unicode, пунктуацией и BOM.
