# #18. Сжатие через хранимую импликацию (исследование)

## Смысл эксперимента

Новая ветка **не содержит отдельного хостового компрессора**. Используется без изменения общий `infer()` из draft PR #16. Входное представление и правило формируются обычными узлами `LinkGraph` (с теми же каноническими пятью полями однотабличной модели). Правило хранится как

```text
Rule = V -> (Sequence([(((X,Y),X),Y)]) -> Sequence([((X,Y),(X,Y))]))
```

где `X,Y` — переменные (структурные ID), `Sequence` — исследовательская `CONS/NIL` проекция, **не доказанная точной формой native FORMAL v0.15**.

`S1` связывает `X,Y` и проверяет повторы, `S2` строит правую часть с hash-consing. Исполнитель выбирает правило только из явно активного контекста `theory`, а исходную последовательность — из `context`. Отдельный независимый **наблюдатель**, а не операция сжатия в runtime, проверяет байтовую эквивалентность декодированной последовательности, число достижимых уникальных дуплетов и ориентировочный размер полной сериализации выбранного корня.

## Проверяемый положительный пример

```text
old: (((м,а),м),а)    = 3 unique internal pairs
new: ((м,а),(м,а))    = 2 unique internal pairs
Decode(old) = Decode(new) = "мама"
```

Правило применяется к прежде невиданным блокам (в том числе смешанному Unicode). Выход — **кандидат** с proofLink и точным `root`, а не принятая мутация памяти. Поскольку исходный граф, правило и provenance остаются в хранилище, **число физических связей после вывода растёт**; фактическое сжатие БД пока **не продемонстрировано**. Запись `((м,а),(м,а))` экономит одну уникальную пару *как автономное представление* при принятии корня, но не учитывает дополнительную стоимость правил, словаря, ссылок и всего корпуса.

## Свидетельства / falsifiers

`tests/compression-implication.test.mjs`: новые переменные, два источника, повтор букв, mixed Unicode, несовпадение повторной переменной, неактивное правило/контекст, replay того же правила через одну физическую SQLite `links` таблицу с rebuilt counters, RESOURCE_LIMIT, запрет скрытого переписывания корня и цикл decode. Никаких скрытых правил «русский язык» либо «опечатка» в исполнителе.

Пока **отсутствуют**: полный формальный контракт семантической эквивалентности, доказанное соответствие FORMAL/ExactSequence, самовыученные преобразования, безопасный GC, глобальная оптимизация MDL, калибровка веса, поиск по корпусу, проверка confluence/termination и производственный механизм переписи памяти.

**PR экспериментальный, без merge.** Сначала независимый научный аудит и решение автора по exact SHA. См. #10, #15, #17, #18.
